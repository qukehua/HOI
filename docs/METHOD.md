# 技术路线、动机与适用边界

## 要解决的问题

设人体轨迹为 H、物体轨迹为 O、接触过程为 C，场景条件为物体几何 G 与人体骨架 S。用户可以只指定其中任意分量，例如“人体轨迹固定，物体跟随手部”“物体通过两个路标，人体自行适应”“第20–40帧左手接触，其他时间明确不接触”。目标是同一模型补全所有未知部分，并同时满足已经指定的条件。

单独合并两篇方法不足以保证研究新颖性。TriDi 给出三模态联合分布与不同生成方向，但其原始任务/数据处理以静态交互为核心；Kimodo 提供人体动作的多种精细控制，却不直接建模物体运动和接触过程。因此这里的可检验问题是：**跨人体、物体、接触的稀疏约束，能否通过关系表示传播到未知部分，并泛化到训练未见的约束组合？**

这仍是待实验验证的假设。已有 HOI 随机掩码、混合条件和物理交互研究，不能据此宣称首次可控 HOI、首次 unified HOI 或已经证明物理可行。

## 表示与输入输出

- H `[T,22,9]`：22个人体关节的世界位置和全局旋转6D。
- O `[T,9]`：单个刚体模板原点的世界位移和旋转6D。
- C `[T,22]`：关节与采样物体表面的接触距离代理。
- G `[K,3]`：物体局部表面点；S `[22,3]`：人体骨架静态偏移。
- 三个逐分量 mask：True 表示已知；0接触与未知接触严格区分。

输入可以只有 G/S/序列长度/速率，也可以附带部分 H/O/C、真实文本嵌入或 Kimodo 生成人体。输出是连续的 H/O/C 序列，不是静态姿态。使用统一米制、Y轴向上，保持整段世界坐标。局部几何不随世界坐标旋转而重复旋转。

没有采用 TriDi 原来的完整高维身体/交互 latent，也没有同时建模精细手指、接触力、关节力矩。此处 C 是22点粗接触代理，与 TriDi 的稠密接触表示不是同一个对象。

## 训练与生成

训练目标为条件补全分布：

`p(H_unknown, O_unknown, C_unknown | H_known, O_known, C_known, masks, G, S, text)`。

1. 从原始序列完成坐标统一、时间连续性切分和接触代理生成；先按源序列分 train/val/test，再切窗口。归一化只使用训练集。
2. 在三种模态上独立抽取扩散时间步；整模态已知时设为0。训练同时抽取七种整体方向和细粒度控制。可从所有来源严格排除某个实际观察组合，例如 H+O。
3. 将带噪状态与 mask 编码成 H/O/C token，融合物体点云、人体骨架、fps与可选文本。每个 block 先做帧内交互，再做时间注意力，避免对全部时空token做一个昂贵的注意力矩阵。
4. 可选粗阶段联合估计根与物体，再作为上下文帮助细化人体/接触。它借鉴 Kimodo 的层级思想，但不是直接复用 Kimodo 原始 denoiser/已训练层，也不声称严格重现其两阶段算法。
5. 可选关系分支把关节变换到物体坐标系，编码最近表面点偏移、距离、接触值和观察标记；关系 token 同时送到人体、物体、接触分支。
6. 优化去噪重建和几何一致性损失。生成采用 DDIM，在每步后恢复已知分量。可选最后的几何修正只通过未指定变量调整接触/FK/滑移，修正后也恢复锚点。

接触修正是梯度优化后的处理，不是动力学求解器，也不是已经实现的每步物理引导。地板损失仅在记录提供校准的 `floor_y` 时启用；不能把相机坐标的零高度当作真实地面。缺少校准时，评估中的零平面统计只作标明假设的诊断。局部滑移损失更适合持续抓持；真实滑动、滚动交互需要单独的接触类型表示，当前版本可能过度约束它们。

## 相比直接融合，实验应验证什么

| 限制/问题 | 已实现的技术手段 | 应检验的结果 |
|---|---|---|
| 每个条件方向单独建模 | 单模型独立 H/O/C 噪声与混合mask | 同一检查点覆盖七种方向和局部控制 |
| 人体控制与物体接触不一致 | 物体局部关系token、双侧几何修正 | H+O+C联合成功率，显式接触间隔，不止锚点误差 |
| 训练条件组合记忆 | 严格留出观察签名 | 未见组合的约束满足与运动质量 |
| 静态帧拼接丢失真实运动 | raw sequence时间戳、世界坐标、时间注意力 | 连续运动、接触滑移与时间一致性 |
| 条件被修正过程破坏 | 去噪/修正反复写入硬条件 | 观察值精确保留，同时未知关系仍改善 |
| 数据近似被误当物理事实 | fps/尺度/proxy来源记录和拒绝报告 | 可追溯的数据筛选及物理评估前提 |

实验至少包括 plain-mask、plain-mask+相同几何修正、mask+coarse、relation 与 relation+修正。各自分别训练/评估，保持数据预算一致；参数量并非完全相同，需要如实报告。多种随机种子，评估完整测试集，并把采样耗时和修正耗时计入成本。

硬条件由程序写回，因此“观察误差为0”主要是接口正确性，不构成模型创新证据。必须同时衡量未指定部分质量、关系满足、未见条件组合、多样性及是否引入新的违约。当前评估脚本没有实现可信的 HOI-FID 或感知评分；不要用 MSE/平滑度替代这些指标。

## 面向物理可执行性还缺什么

当前输出是运动学参考轨迹，关节位置与旋转可能不完全符合 FK，几何代理也不能检查完整人体/物体网格穿透。硬位置锚点与 FK、接触约束冲突时不能同时保证全部成功，评估应暴露冲突。

下一阶段需要从姿态构建带质量、惯量、碰撞体与关节限制的仿真人体/物体，训练或接入能跟踪参考动作的闭环控制器，并报告控制受限条件下的实际成功率、跟踪误差、滑移、物体掉落、跌倒、力矩与接触力。对比“原始生成”和“利用执行反馈改进后的生成”才能把研究贡献推进到可执行 HOI。此处尚未实现这层控制器，不能将当前项目称为物理可执行系统。

BEHAVE 已取得 SMPL-H 并完成全量转换与逐条数据校验，联合清单已生成；完整双数据集训练实验尚未运行。OMOMO 原始fps还没有元数据确认；默认30fps是记录在案的假设。稀疏关节点接触代理、尺度固定近似以及排除多部件物体均限制当前研究范围。

## 官方代码使用情况

TriDi：直接保留 MIT 许可的 Projection 与时间编码函数，并记录原始commit；联合独立时间步思想扩展成新的时序实现。Kimodo：核对并接入官方推理 API，提供 SMPL-X22 导出桥，明确转换其列式rotation6D与本项目行式rotation6D的差异。更多来源见 [UPSTREAM.md](UPSTREAM.md)。

两者的预训练权重不能直接装进这里的新网络。Kimodo 公开库没有训练trainer；本项目的训练、时序三模态模型、关系编码和控制协议为新增实现。几步 smoke 检查不意味着复现论文结果或获得生成能力。
